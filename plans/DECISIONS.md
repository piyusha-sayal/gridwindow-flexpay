## Retry policy (D-010 … D-013)

| Situation | Automatic action | Why / limit |
|---|---|---|
| `CREATE_ORDER` STARTED/AMBIGUOUS, quote unexpired | Replay stored request, same key, lease holder only | Recovers a lost response; same key cannot create a second order |
| `CREATE_ORDER` any status, quote expired | None → `CANCELLED` (`ORDER_CREATION_ABANDONED`); if a provider call was attempted, also `MANUAL_REVIEW_REQUIRED` | Buyer never saw an approve link; new terms need a new quote; quote TTL is always far inside the 6 h request-id retention (D-013) |
| `CREATE_ORDER` definitively rejected (4xx) | None → `FAILED` | Replay would repeat the rejection |
| `AUTHORIZE` ambiguous or 4xx | Reconcile from `GET order` / `GET authorization`; never re-authorize under a new key | Provider may already hold the authorization |
| `CAPTURE` STARTED/AMBIGUOUS (crash, timeout, 5xx), authorization unexpired | Replay same key, then re-read capture | Same key returns the original capture |
| `CAPTURE` definitively rejected (4xx) | None; `MANUAL_REVIEW_REQUIRED` event | Operator review |
| Capture `PENDING` | None; wait for verified `PAYMENT.CAPTURE.*` webhook, operator reconcile or restart sweep → `GET capture` | Never a second capture while pending |
| Capture `DECLINED`/`FAILED` | None → `CAPTURE_DECLINED`, capacity released | Any new charge requires **renewed buyer consent** (new offer, new order, new approval) |
| Authorization expired before capture | None → `NEEDS_RECONCILIATION` | Capture ineligible; renewed buyer consent required |
| Capture amount/currency/authorization mismatch or unknown status | None → `NEEDS_RECONCILIATION` | Manual intervention; fail closed |
| `VOID` STARTED/AMBIGUOUS | Replay same key, then re-read authorization | Releases the buyer's hold |
| Model/LLM output | Never triggers any payment operation | CLAUDE.md invariant 3 |
